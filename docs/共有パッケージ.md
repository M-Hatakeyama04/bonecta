# 開発会社への共有パッケージ案内

発注・見積依頼時に、以下をセットで渡す。

---

## 1. 必ず渡す資料

| # | ファイル | 説明 |
|---|----------|------|
| 1 | [`開発依頼書.md`](./開発依頼書.md) / [HTML](./html/brief.html) | 依頼目的・要件・検収・スコープ記入欄 |
| 2 | [`VIDEO_SPEC.md`](./VIDEO_SPEC.md) / [HTML](./html/spec.html) | 動画の詳細仕様（表示ルール・UI） |
| 3 | 本リポジトリ（ソース） | 動作する Python プロトタイプ |
| 4 | サンプル MP4（別送） | 18 パターンの完成例。Git には含めない想定 |
| — | [`html/index.html`](./html/index.html) | 上記のブラウザ閲覧用パッケージ入口 |

## 2. サンプル動画の渡し方（推奨）

`output/` は容量が大きいため Git に含めない。共有時は次のいずれか。

- Google Drive / Dropbox 等に `output/go2senkyo/*/slug.mp4` だけを zip
- または代表 5〜6 本だけ渡す（01, 07, 08, 11, 13, 直接動画があればそれ）

zip 例（ローカル）:

```bash
cd output/go2senkyo
zip -r ~/Desktop/bonecta-sample-mp4s.zip \
  */*.mp4 \
  batch_summary.json
```

## 3. 依頼時に発注者が決めること

`開発依頼書.md` の「見積依頼時に指定する項目」を埋める。

特に重要:

1. **スコープ**（仕様どおりの生成のみ / API化 / 画面 / Bonecta統合 など）
2. **納期・予算**
3. **サンプル MP4 の共有方法**
4. テロップを現状のルール分割のままにするか、LLM 化するのか

## 4. 開発会社側の最初のアクション（推奨）

1. 依頼書・VIDEO_SPEC・サンプル MP4 を読む
2. プロトタイプをローカルで 1〜2 本再生成して再現する
3. 不明点リストを返す
4. スコープ確定後に見積

## 5. 再現コマンド（プロトタイプ）

```bash
pip install -r requirements.txt
# ffmpeg / ffprobe が必要
python scripts/batch_go2senkyo.py --force
```

依存の詳細・UI 数値は `VIDEO_SPEC.md` を正とする。
